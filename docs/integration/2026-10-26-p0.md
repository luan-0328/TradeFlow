# P0 多商家权限、真实联调和恢复验收

本轮按用户要求完成四项 P0；只使用本地新建隔离依赖，不部署、不 SSH，不迁移现有业务库、不停止既有服务、不提交推送。本文记录分层结果，不把构建、Mock 或单应用测试当作整套业务通过。

## 实现

- 每店独立 ADMIN / OPERATOR。用户库追加 V7，身份与 capabilities 返回 merchantRoles；旧全局商家角色不能授予店铺权限，旧五参 AuthContext 兼容构造器生成空职级。入驻审批授本店 ADMIN，角色修改撤销目标令牌，与审计同事务；保护最后有效管理员，并提供平台真实商家编号与明确职级的恢复表单。
- 各服务按当前选店职级和资源归属授权；商品、图片、库存、运费和成员维护要求本店 ADMIN，履约及售后允许本店 OPERATOR。网关保留选店输入，由下游核验，不把选店头当身份凭据。
- 独立 Rabbit Exporter 核对交换机、队列、参数、策略及完整绑定；生产 Prometheus 规则报告拓扑漂移。SENT 原事件补投保存原 ID 和冻结正文，保留资金 guard、租约围栏、Inbox 去重与审计；后台提供历史原事件入口、明确重复投递说明及必填补投原因。
- 新增独占八服务和浏览器验证脚本，使用临时凭据、最小运行账号、随机回环端口、专用 Nacos namespace、真实 RabbitMQ / Redis / MySQL；结束时按 PID 映像和创建时间核验后清理。

## 验证中修复的问题

1. 退款重试在校验当前店归属前返回历史幂等结果，可能在撤权/换店后读到旧店售后。先复现回归失败，再把归属校验前移；同店仍原号返回、不增加远程调用。
2. 平台成员表单固定演示商家且遗漏职级，无法恢复真实店 ADMIN。改为实际商家输入和显式角色。
3. 网关旧身份头过滤误删选店输入，真实多店链路返回 MERCHANT_SELECTION_REQUIRED。回归复现后保留该业务输入，伪造身份及内部 Token 仍清除。
4. 管理后台原先隐藏 SENT 重投能力。三服务仅为有冻结正文的 SENT Outbox 提供补投动作；历史 SENT 不计故障待办，后端仍做完整状态和原文校验。
5. 本地 fixture 的 Java shim、增量产物检查和 Sentinel 初始化开关导致启动失败。已使用真实 java.home、按模块依赖校验产物，并关闭 eager / SCG 独立开关；保持非回环监听即拒绝，不修改官方包或系统防火墙。

失败尝试保留，不计通过：早期隔离栈遇到 Sentinel 监听、失效 Nacos 和旧网关过滤问题；首轮浏览器遇到脚本定位/导航问题。相关测试进程均以独占身份清理，原始证据保留在 `.local`。该目录含受保护临时秘密，不能整体发布。

## 边界

本地 Nacos 使用 SHA256 固定的官方 3.3.0-RC，以满足 Raft 全监听回环隔离；业务应用仍使用工程现有 SDK。实际 HTTP 已使用真实发现，不存在直连替代。RC 仅用于本地 fixture，不是生产版本选型或升级结论，详见 [隔离说明](2026-10-25-nacos-isolation.md)。

支付是独立模拟通道，结算是模拟出款；不代表真实渠道或银行清算验收。性能容量、高可用、生产备份灾备和线上部署不属于本轮完成声明。MQ 补投不是每消费者 ACK 的全局投递账本；影响区间和恢复结果仍需按专项运行步骤核验。
