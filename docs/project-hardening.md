# 单商家单仓库加固交付（2026-10-25）

本轮仅修改、构建和验证本地代码，没有SSH、服务器部署、提交推送、迁移现有业务数据库或重启既有服务。范围确认单商家`merchant_demo`、单仓库`warehouse_main`；没有引入Seata或扩大结算业务。

## 实际业务改动

1. **退货认可与商品可再售分离**。商家认可退货时须逐件指定SALEABLE、QUARANTINE、DAMAGED或SCRAPPED，不选择不能提交。售后冻结处置，订单核对原授权购买件并保存权威收据，商品只按权威收据处理。仅SALEABLE增加可售，待检/残次保存独立余额，报损仅保留事实。资金退款义务不因商品不可再售而取消。
2. **待检和残次可继续处置**。商家管理员可按原键、SKU、数量和依据，将待检/残次转其他条件、可售或报损；源余额原子扣减，目标余额、可售流水、审计和幂等结果同事务，余额不足或末步失败整笔回滚。原退货记录不改写。前端刷新丢失原表单后，可输入原SKU并按原日记键只读查询受理结果；未查到保持未知，不换键重建。
3. **支付旧租约漏洞修复**。原执行者租约已过期但无人接管时，旧代码仍可能应用成功资金事实。现统一检查owner、claim_version及数据库有效租约，完成条件更新为零行会回滚同事务业务效果；关闭和退款完成也沿用同一围栏。
4. **实际业务入口保护**。登录在用户库原子约束账号/来源窗口；网关Redis Lua约束分类总额与主体额度，失败503，超额429并带Retry-After。来源默认socket，明确不相信客户端来源头。Redis重启/驱逐可能重置临时配额，资金/库存约束仍在数据库。
5. **平台人工待办**。14类来源独立读取、分页和显示错误；不把当前页当全量，不把读取失败当零待办。受控恢复沿原任务、原因和幂等键，不提供直接改成功或新建未知退款执行号的按钮。
6. **备份可校验**。归档保存实际字节散列和证据索引，拒绝越界/链接/损坏/身份错配及原注册中心、MQ复用的恢复计划。隔离MySQL合成数据恢复已实跑，真实业务Compose恢复仍未验收。

## 升级与运行

新增迁移：用户V5、商品V5、订单V7、售后V4，共新增5张表；表与字段具有中文COMMENT，旧迁移未改写。源码业务表目标由92增至97，既有开发/服务器数据库没有在本轮被自动升级。运行账号授权脚本同步增加新表，资金、处置流水及原验收记录保持只追加。

历史已认可验收按旧语义回填SALEABLE；新验收必须显式逐件处置。此次内部收据增加处置字段，升级应停写并协调更新售后、订单、商品，不能混用旧JAR处理新验收。启动前准备Nacos和Redis；发布前按备份、迁移、授权、启动顺序验证，不直接把新前端接到旧后端当新版本验收。

本机`Start-Local.ps1`调用`Prepare-Redis.py prepare`准备本项目专用回环16379实例；密码仅保存受保护文件，启动不在命令行带密码。端口、PID创建时间、映像、配置路径与归属标记不符均拒绝接管；单独`python scripts/Prepare-Redis.py stop`只停项目归属实例且保留数据。详见[本机Redis](runbooks/local-redis.md)。Compose新增私网Redis及网关就绪依赖；此Compose增量未实际容器部署。

## 尚未完成的验收

真实Nacos发现未通过本机隔离前置检查：官方3.0.3虽然HTTP与SDK接口绑定回环，内置Raft端口仍通配监听。没有Docker，WSL组件未安装；本轮没有放宽网络隔离、改防火墙或篡改官方二进制，已停止自建Nacos。SDK集成源码编译通过，但该集成用例实际安全跳过1项，不能算发现联调通过，见[Nacos证据](integration/2026-10-25-nacos-isolation.md)。

需要合适的本地隔离运行环境后，继续七服务真实Nacos联调、本轮前端业务交互、MQ停机/确认丢失/乱序、完整对账造差及备份业务恢复。服务器扩容、部署和性能压测未执行；没有高可用、吞吐量、生产规模或完整故障验收结论。
