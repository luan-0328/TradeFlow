## Architecture

已有支付和退款Outbox切到RabbitMQ，不再自动HTTP降级。旧HTTP内部结果接口保留，幂等业务仍保护重复入口。订单消费支付/退款，售后消费退款，订单消费审计事件。订单、售后新增本库Outbox发布OrderPaid/OrderClosed/AftersaleCompleted；订单审计投影不执行资金/库存。

统一事件Envelope：eventId,eventType,eventVersion=1,aggregateType,aggregateId,aggregateVersion,occurredAt,correlationId（订单号）,causationId,traceId,payload。payload对资金为完整ChannelFact（不嵌套fact），对审计为orderNo/aftersaleNo等不可变事实。旧支付outbox.payload仍存Event{eventId,fact}，publisher首次领取后按既有行元数据包装并持久wire_payload，后续重放完全相同字节。DTO在contracts，基础设施在common-web com.tradeflow.messaging，Gateway不依赖。

Topic exchange tradeflow.events：PaymentSucceeded→payment.succeeded.v1、PaymentFailed→payment.failed.v1、PaymentClosed→payment.closed.v1；RefundSucceeded/RefundFailed→refund.succeeded.v1/refund.failed.v1；OrderPaid/OrderClosed/AftersaleCompleted→order.paid.v1/order.closed.v1/aftersale.completed.v1。durable classic队列q.order.payment/q.order.refund/q.aftersale.refund/q.order.audit和各自同名.dlq；独立topic DLX tradeflow.dlx，routingKey为原queue+.dlq。消息persistent，发布mandatory+correlated confirm且无return才SENT，不声称exactly-once或单节点高可用。拓扑在独立本机准备脚本由管理员导入；业务账号不拥有配置其他服务资源权限，不在业务启动声明全拓扑。

## Consumer durability decision

消费者本地inbox(consumer_name,event_id)+业务效果/后续任务同事务，提交后ACK。哈希按事件规范化JSON（对象键排序），同ID异内容隔离且不覆盖旧inbox。合法前置条件暂缺或短暂错误持久deferred_event并ACK，由数据库任务按原ID独立重试业务，不能被已有DEFERRED inbox挡掉；成功同事务将inbox/deferred标APPLIED。这是数据库持久重试交接，不是声称转发到了Rabbit重试队列。网络一律在事务外。

Schema/金额绑定/不可恢复冲突持久message_failure隔离原始载荷和原因。超限deferred也隔离；独立DLQ发送器向对应durable DLQ confirmed+mandatory发布原正文，保留原eventId和失败头，失败继续保留本库记录。ACK表示本库可靠接收，broker DLQ发布有自己的持久状态；不能把尚未发到broker说成DLQ已送达。数据库不可用不ACK，消费者有限退避后NACK requeue，不形成快速无限循环。

deferred、DLQ发布、Outbox均30秒租约/owner/claim_version，领取立即提交、回写重验围栏。5s/15s/60s/300s/900s有界退避，10次或30分钟转人工。旧执行者网络副作用仍靠原事件/业务号幂等。事件版本不支持隔离，不按aggregateVersion随意丢资金事实。

## Stable shared API for integration

- contracts.MessagingContracts.Event（Map<String,Object> payload，以上字段）；构造器record，不能共享实体。
- messaging.EventHandler: String consumer(); Set<String> eventTypes(); void handle(Event event)。handler只做本地事务业务，无RPC，基础设施调用时已在外层TransactionTemplate内。
- messaging.OutboxGuard: void check(String aggregateType,String aggregateId)。支付实现本地检查payment/refund review与绑定，不持锁网络；默认允许审计事件。
- messaging.MessageOutbox.enqueue(String aggregateType,String aggregateId,long aggregateVersion,String eventType,String orderNo,String causationId,Map<String,Object> payload) 返回String eventId，强制已有本地事务，和业务同提交。此append bean不受transport开关影响，有DataSource时可注入。
- messaging.MessageOperations.list(String kind,int page,int size) 返回Object，kind只outbox/deferred/failure；retry(String kind,String id,String actor,String reason) 返回Map<String,String>。只原ID/原body重放，原因和操作审计同事务，不能任意改payload或资金。各服务Controller负责最新平台身份，基础设施不接触用户RPC。旧outbox使用event_id，deferred/failure可自定安全稳定id并报告。
- 基础设施提供AutoConfiguration（注册imports），tradeflow.messaging.enabled=true控制网络发布和消费；tradeflow.messaging.consumers是该服务队列对应consumer列表，如order.payment,order.refund,order.audit；aftersale.refund。队列名为q.+consumer。publisher及listener没有注册handler的服务不消费该队列。
- 新增各参与库inbox_message/deferred_event/message_failure/message_operation表；订单、售后新增outbox_event（结构与支付一致且有wire_payload LONGTEXT）；支付追加wire_payload。不改历史V1，root统一迁移生成/授权，基础设施implementer提供准确DDL文件模板到docs/database-target/b5-messaging-tables.sql、b5-outbox-table.sql、b5-payment-alter.sql供root复制为新迁移。
